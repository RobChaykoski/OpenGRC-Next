## Fixed today

1. **`1a24e8d` Container healthcheck.** The image probed
   `http://localhost/app/login` with a bare `localhost` Host header. On a
   deployment whose `APP_URL` is an IP, `TrustHosts` answers 400, so the app was
   marked unhealthy and `worker` refused to start
   (`dependency failed to start: container opengrc-app-1 is unhealthy`). The
   new `docker/healthcheck.sh` derives the Host header from `APP_URL` and probes
   loopback, so the same image works for loopback and real hosts.
2. **`3fc7eb4` Migration manifest.** `database/migration-manifest.json` was
   generated from a stale CRLF working tree, so a fresh LF checkout failed
   `Migration integrity` on
   `2026_01_28_191859_seed_data_manager_permissions`. The manifest now hashes
   the LF git blobs; `.gitattributes` already enforces `eol=lf`.

## Authentik SSO (configured)

- Authentik application **OpenGRC** (`slug=opengrc`, OAuth2 provider `pk=3`,
  confidential, `authorization_code` + `refresh_token`, redirect
  `http://172.16.16.88:8080/app/oauth/callback/authentik`).
- OpenGRC reads the client settings from `AUTHENTIK_*` in `~/opengrc/.env`;
  Compose forwards them explicitly to the app container.
- Login links an IdP identity to an existing OpenGRC account by email.
  Unknown identities are refused rather than auto-provisioned.
  - `akadmin` (`admin@swocts.com`) maps to the break-glass OpenGRC admin.
  - `swocts` (`rob@swocts.com`) maps to a new OpenGRC admin created for the
    operator; the local password is in `~/opengrc-rob-password.txt`.
- Verified end to end in a headless browser: OpenGRC → Authentik flow → callback
  → `/app/me?require_two_factor=1` (the privileged 2FA gate). The session is
  valid; enrol a TOTP to reach the dashboard.
- The login screen now uses the range's slate-and-blue surface with the
  Authentik button under the password form.

> The image has no `.env` and PHP-FPM clears the process environment, so the
> entrypoint's `config:cache` is what makes `APP_KEY` and the database settings
> visible. Do not run `config:clear` in the running container without running
> `config:cache` again; the login page will 500 with a missing APP_KEY.
