## Fixed today

1. **`1a24e8d` Container healthcheck.** The image probed
   `http://localhost/app/login` with a bare `localhost` Host header. On a
   deployment whose `APP_URL` is an IP, `TrustHosts` answers 400, so the app was
   marked unhealthy and `worker` refused to start
   (`dependency failed to start: container opengrc-app-1 is unhealthy`). The
   new `docker/healthcheck.sh` derives the Host header from `APP_URL` and probes
   loopback, so the same image works for loopback and real hosts.
2. **`3fc7eb4` Migration manifest.** `database/migration-manifest.json` was
   generated from a stale CRLF working tree, so a fresh LF checkout failed
   `Migration integrity` on
   `2026_01_28_191859_seed_data_manager_permissions`. The manifest now hashes
   the LF git blobs; `.gitattributes` already enforces `eol=lf`.
