## Open items, stated plainly

1. **Dev DB migration checksum drift.** 107 old applied checksums differ from the
   current files. Recreate the dev volume or reconcile deliberately; do not
   silently rewrite the table.
2. **Assistant writes are not built.** The catalogue is read-only. Human-approved
   writes need an approval object, actor, diff and rollback, with their own ADR.
3. **Assistant questions are a fixed catalogue.** A new question is a reviewed
   query and a test, not a prompt edit. Unmatched questions are refused.
4. **DLP is partial.** No first-class policy object, no suppression/exception
   workflow with expiry, no exact-data-match or document fingerprinting, and no
   measured recall. The quality page measures false positives only.
5. **DLP findings do not link to risks/controls.** The risk handoff is manual.
6. **Architecture page is current-state only.** Target state, deployment
   location, roadmap and “deliberately not implemented” are document/risk records,
   not database fields.
7. **Access rules are platform-wide.** No per-OAuth-client or per-application
   lists; email-domain rules act after authentication for panels; CLI account
   creation applies email rules but not IP rules.
8. **Reference status matters.** Managed Sentinel is 2019/CSF 1.1-era; AIDA is
   archived and was proposed, not enacted; the CCCS career guide is 2022 and is a
   career guide, not a competency framework.
9. **No production promotion.** The deployment is the local Compose stack. A
   production deploy needs a backup, the supported install/upgrade path, MFA
   enrolment for privileged accounts, and a fresh doctor.
10. **Streaming monitoring is still not built.** Connectors remain scheduled and
    write evidence after the fact.

## Addendum: access governance (ADR 0049)

Shipped the governance plane for real-time and just-in-time access:

- `ProtectedResource`, `AccessPolicy`, `AccessGrant`, `AccessDecision` (append-only,
  hash-chained), enums, factories, `AccessPolicyEvaluator`, `ExposureService`,
  `AccessGrantService`, and `opengrc:access:expire-grants` (scheduled every five
  minutes).
- New app-panel group **Access governance**: Overview, Protected resources, Access
  policies, Access grants, Access decisions. Decisions are read-only for every role.
- Tests: `tests/Feature/Access/` (25 decision/lifecycle tests, 8 route tests).
  Full suite, Pint, PHPStan and doctor pass; migration manifest and schema snapshot
  regenerated.

Not built yet, deliberately:

1. **No enforcement endpoint.** The integration contract is documented in
   `docs/grc/access-governance.md`; an API route, authentication and idempotency
   keys still need an implementation and their own ADR.
2. **No OPA/Trino adapter.** The policy table and rule hash are the inputs; the
   adapter is a separate service.
3. **No relation managers** on the resource pages (grants/decisions per resource).
4. **No seeded policies.** A fresh install has no access policy, which means every
   evaluation denies. That is the safe default, not an oversight.
5. **Exposure is relative weight, not money.** Thresholds are configuration, and
   there is no calibration or recall measurement behind them yet.

## Addendum: Gophish awareness evidence (ADR 0050)

Shipped a read-only Gophish connector for the awareness programme:

- `EvidenceSourceType::Gophish`, registered in `ConnectorRegistry`.
- `GophishConnector` reads `GET /api/campaigns/` and
  `GET /api/campaigns/{id}/summary` only. One record per campaign, type
  `awareness-training`, external id `gophish:campaign:{id}`.
- Payload is aggregate only: counts, rates (denominator `sent`, falling back to
  `total`), campaign dates, campaign/template/page/group names. No target rows, no
  timeline, no user agents, no submitted values, no template HTML.
- Status is always `unknown`: a validation rule compares the rates to the
  organisation's own target. Completed campaigns are measured at the completion
  date (re-collection deduplicates); running campaigns at collection time.
- Bounded by `lookback_days` (180) and `max_campaigns` (25, cap 500). Base URL is
  operator-configured, http/https only, GET-only via `grcReadOnly`, no redirects,
  TLS verification kept on, optional CA bundle.
- `awareness-training` is also accepted by the hash-verified evidence API, so a
  different simulator can submit the same contract.
- Tests: `tests/Feature/Evidence/GophishConnectorTest.php` (16) plus a Filament
  form test in `EvidenceSourceUiTest`.

Docs: `docs/integrations/gophish-awareness.md`, ADR 0050, decisions index (0049
was missing from it and is now listed), ecosystem integration and tooling maps.

Not built yet, deliberately:

1. **No per-person result.** OpenGRC cannot answer "who clicked"; that stays in
   Gophish under its own access and retention.
2. **No campaign creation.** OpenGRC reads a campaign; it never starts one.
3. **No trend read model.** One record per campaign per measurement; a trend
   report would need a read model.
4. **No report-timing measure.** The summary endpoint exposes `email_reported`
   but not time-to-report.
5. **Not exercised against a live Gophish instance.** The connector is covered by
   `Http::fake` tests and the documented summary shape; a first live run should
   use a small campaign and `--dry-run`.

## Addendum: access decision endpoint (ADR 0051)

The governance plane from ADR 0049 now has a consumer:

- `POST /api/v1/access/decisions`, Sanctum token with `access.decide`, bound to a
  client; browser sessions refused. The token's `client_id` is the enforcement
  point (`pep`), the idempotency scope and the rate-limit key.
- The caller asserts subject, resource, profile, trust, zone, purpose,
  justification/device booleans and a reason code. Exposure, tier, grant state,
  policy and answer are computed here; `exposure_weight` and `grant_active` in
  the body are ignored.
- Optional `Idempotency-Key`: a replay returns the recorded decision and appends
  nothing; the same key with a different request is `422`. Unique index on
  `(pep, idempotency_key)`; `request_hash` makes a reused key visible.
- Unknown or soft-deleted `resource.ref` is an audited deny
  (`unknown_classification`), not a 404. The human `PR-00042` id resolves too.
- Response is `action`, `reason`, `ttl_seconds`, `correlation_id`,
  `policy_version`, `rules_hash`, `Cache-Control: no-store`.
- Exposure now counts permissive decisions only. Denied, masked and filtered
  decisions no longer push a subject toward step-up.
- Per-token throttle on this route (default 600/min, `ACCESS_DECISION_RATE_LIMIT`)
  instead of the shared 60/min API limit.
- Migration `2026_11_21_090400_add_decision_replay_columns_to_access_decisions_table`
  adds `idempotency_key` and `request_hash`; manifest and schema snapshot
  regenerated (160 migrations).

Tests: `tests/Feature/Api/AccessDecisionApiTest.php` (24) and
`tests/Feature/Access/ExposureServiceTest.php` (6). Full suite 839 passing.

Not built, deliberately:

1. **Break-glass decisions do not mint a grant.** The `time_boxed` answer is
   recorded, but the privacy review obligation still has to be raised through the
   grant workflow. Auto-granting needs an ADR (requester identity, justification
   text, post-hoc approval).
2. **No batch endpoint.** One request, one decision, one key.
3. **No subject account link.** Grants match on subject type and label; the
   contract carries no account id, so a drifted label stops matching silently.
4. **No retention or pruning.** Decisions are evidence; retention is a legal
   decision.
5. **No OPA/Trino adapter** and no revocation callback from a clinical system.
