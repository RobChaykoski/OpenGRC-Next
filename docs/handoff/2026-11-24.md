Point-in-time note for the work on `chore/lts-baseline`. The session opened on

## Review findings and fixes

**DLP answer-key flags were deployment-specific.** The detector matched `OCR`
and `TRAILLINE` literally, which put one environment's flag format in the
product. Prefixes now come from `DLP_ANSWER_KEY_PREFIXES` (default
`OCR,TRAILLINE`), are `preg_quote`d, and an empty value disables the detector.
The new infrastructure and answer-key patterns also had no tests; there are now
tests for private and public IPv4, documentation ranges, internal hostnames,
the cloud metadata endpoint, and configured flag prefixes.

**Registration claimed a scan that never happened.** `last_scanned_at` was set
on every registration, so an artifact with no scan tool looked scanned. It now
moves only when `--scan-tool` is named; a later re-registration preserves the
previous scan record.

**An approval could not identify its bytes.** `--skip-hash` plus `--approve`
produced an approved artifact with no content hash. Approval is now refused
without a content hash, alongside the existing refusal for pickle-format files.

## The register is now operable

`Entities → AI models` lists registered artifacts and shows a read-only view
with the format handling class, hashes, conversion record, scan state, owner,
serving asset and approval. Registration stays on the CLI because it walks and
hashes a server-side path; the screen never accepts a path or an upload.

- **Approve** records the signed-in user and the current time.
- **Withdraw approval** returns the artifact to Proposed.
- **Retire** decommissions it without deleting the history.
- Per-file hashes and related findings have read-only relation managers.
- Findings raised by the registrar now link back to the artifact, and the
  finding queue filters by artifact.

The screen hides approval for pickle-format and unhashed artifacts, and the
action re-checks eligibility on the server. Approval writes to the activity log
through the existing model logging.

ADR 0059 is marked accepted with an implementation note: the register, readers,
findings and approval screen are implemented; the runtime-version finding is
not. The register therefore records the runtime on the serving asset or in the
notes for now. This is stated in `docs/grc/ai-model-artifacts.md` and in the
capability map's gap list.

## Addendum: Prismor receipt and attestation import

ADR 0060 is accepted and its first slice is implemented. The boundary is the one
written earlier: the gateway enforces and owns raw telemetry; OpenGRC imports the
decision metadata, not the prompt or tool input.

- `PrismorReceiptVerifier` recomputes Prismor's chain hash over the seven
  normalised fields plus `seq` and `prev_hash`, verifies the Ed25519 signature
  over `{hash, ts, identity}`, and checks `signing_key_id` against the key. A
  pinned key is required; the inline key is accepted only with
  `--allow-unpinned` and is marked low confidence.
- `PrismorReceiptImporter` is fail-closed: a failed receipt or a broken chain
  link rejects the whole batch. A sequence gap is reported, not rejected.
  Re-importing the same device/event is a duplicate; the same identity with
  different bytes is a conflict.
- `opengrc:evidence:prismor` accepts one receipt, a JSON array, or JSONL, plus
  `--pubkey` or `--pubkey-file`, `--control`, `--asset`, `--source`,
  `--dry-run` and `--json`.
- The evidence payload is a whitelist of decision metadata, hashes and the
  signature. It does not contain a tool input, command, prompt or output. The
  record is `Unknown` status: a block is evidence that the boundary operated,
  not an automatic control verdict.
- Added an `EvidenceSourceType::Prismor` case. No schema change and no new
  dependency; Ed25519 uses the existing sodium extension.

Tests: `tests/Unit/Evidence/PrismorReceiptVerifierTest.php` (8) and
`tests/Feature/Evidence/PrismorReceiptImportTest.php` (13). The verifier accepts
Prismor's published example and rejects a changed verdict, a changed device, a
foreign pinned key, a tampered signature, a malformed receipt and an unsupported
algorithm. The importer covers control linking, deduplication, tampering,
unpinned mode, dry run, an unknown control, a sequence gap, a broken chain link,
duplicate sequence numbers, a duplicate identity in one batch, a public-key file,
JSONL input and a re-signed conflict.

### Attestation bundle

The same source now has a signed attestation import:

- `PrismorAttestationVerifier` recomputes the SHA-256 of the JCS-canonical bundle
  body, verifies the Ed25519 signature over `{hash, ts, identity}`, and checks
  the key id against a pinned key. Objects and arrays are kept distinct while
  canonicalizing, so an empty object stays `{}` rather than becoming `[]`.
- `PrismorAttestationImporter` stores only the agent inventory, discovery
  summary, framework/control IDs and covered flags, audit-finding counts, the
  trail checkpoint and the signature. Audit messages, raw MCP URLs, provider-key
  locations and the bundle body are dropped.
- `opengrc:evidence:prismor-attestation` accepts one bundle with the same
  pinning, control/asset, dry-run and JSON options as the receipt command.
- A body edit breaks the content hash; a device-id edit also breaks the
  signature. A re-signed bundle with the same content hash but a different
  signature is a conflict, not a duplicate.
- The fixture is independently signed with Prismor's published canonicalization
  and carries synthetic MCP URLs and audit messages to prove the whitelist.

Tests: `tests/Unit/Evidence/PrismorAttestationVerifierTest.php` (8) and
`tests/Feature/Evidence/PrismorAttestationImportTest.php` (6). Coverage includes
pinned/unpinned verification, body and device tampering, a foreign key, an
unsigned bundle, a wrong schema, JCS object/array behaviour, control linking,
deduplication, dry run, an unknown control, and a payload that contains none of
the synthetic secret paths or URLs.

### Sensor summary import

Phase 3 of ADR 0060 is a generic aggregate summary contract for Suricata, Arkime
and Cilium Hubble:

- `opengrc:evidence:sensor-summary` accepts one normalised JSON object with a
  source, sensor, window, counts, verdict/protocol maps, service counts, service
  edges and sensor health.
- `--sha256` checks the exact file bytes; `--allow-unhashed` stores the summary
  as low confidence. A hash-verified summary is medium confidence: it proves
  byte integrity against the operator-supplied hash, not authenticity.
- Extra fields such as raw events, URLs and payloads are ignored by the
  importer, and the stored payload contains only the whitelisted aggregates.
- The record type is `sensor-summary`; the source type is `Sensor`; the status is
  `Unknown`, so a validation rule or reviewer decides what the counts mean.

Tests: `tests/Feature/Evidence/SensorSummaryImportTest.php` (7). Coverage
includes control linking, deduplication, a wrong hash, the unhashed opt-out, dry
run, an unknown control, a wrong schema, and a payload that contains none of the
synthetic raw fields.

Arkime (Apache-2.0) is added to the sensor boundary as a full-packet store:
OpenGRC may import session counts and sensor/retention health, but never a PCAP,
payload or raw session export. A bounded capture remains an investigation
artifact under ADR 0019.

## Still open

1. **Runtime inventory.** ADR 0059's "unsupported inference runtime" finding is
   not implemented. A runtime and version field plus a configured baseline would
   be its own change.
2. **Registration is CLI-only.** Deliberate; an upload endpoint would make the
   web container a model store.
3. **Multi-tenancy.** ADR 0057 remains proposed and unimplemented.
4. **Network-flow telemetry.** ADR 0058 remains proposed. The Suricata,
   Pipelock and AI-agent-gateway references gathered at the end of the session
   produced ADR 0060, and its first slice (Prismor receipts and attestations plus
   hash-verified sensor summaries) is implemented. Pipelock, the push endpoint,
   direct sensor connectors and a first-class agent inventory remain future
   work.
5. **Production promotion.** Still an operator action; there is no production
   environment in this repository.
