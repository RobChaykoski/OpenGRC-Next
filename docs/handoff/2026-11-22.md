## What changed

**DLP suppressions are now visible where the decision matters.** An approved
suppression used to exist as a record with no effect on any screen. It is now:

- resolved per finding by `DlpSuppressionResolver`, bound as a scoped singleton
  so the finding table and the quality page share one in-force query per request;
- shown as an **Accepted by** badge in the finding queue (reference `DS-0001`);
- creatable from a finding with a **Suppress** action, seeded from the finding's
  policy, identifier type and match label, and still requiring a second approver;
- counted on the DLP quality page as **Accepted**, overall and per identifier
  type. It does not change the false-positive rate: a suppression is an
  acceptance, not a review outcome.

No schema change, no new table. The resolver matches policy, then the optional
identifier type and match label, reusing `DlpSuppression::appliesTo()`.

## Addendum: evidence stream operations screen

`Admin → System → Evidence streams` now shows each stream's client, name, active
state, last accepted time, last cursor, accepted and rejected counts and the last
rejection reason. Admin-only, because the row carries the signing secret even
though the screen never renders it. An admin can disable a stream (the producer
gets `403` immediately) and enable it again; creating and rotating a secret stay
on the CLI per ADR 0054.

`EvidenceStreamPolicy` is mapped explicitly in `AppServiceProvider`: the
project's `guessPolicyNamesUsing` returns `AppPolicy` for unmapped models, so a
new policy is inert until it is added there. That is worth remembering for the
next model with its own policy.

Tests: `tests/Feature/Evidence/EvidenceStreamUiTest.php` (3) — counters rendered
and secret absent, editor/viewer forbidden, disable and enable through the table
action. Tagged `v0.1.0-alpha-8`; stack rebuilt, doctor strict green.

## Addendum: the assistant producer and the audit ledger

- **Assistant producer (ADR 0055).** An overdue-tests answer now offers
  **Propose next test dates**. It creates one bounded proposal (max five) for
  implementations that are overdue or undated, with the next test date 90 days
  out, linked to the assistant run. Editors only; approval and apply are still
  two separate human steps. Tests in `AssistantTest`.
- **Audit ledger (ADR 0056).** Every activity event is mirrored into
  `audit_ledger_entries`: hash-chained, append-only at the model layer with
  database triggers, properties hashed rather than copied. `opengrc:audit:verify`
  and a new doctor check fail on a broken chain or an altered activity row, and
  report pruned activity as information. 11 tests cover the mirror, the chain,
  tamper detection, triggers, pruning and the command.
- The ledger is a mirror, not a replacement: a write path that bypasses activity
  logging stays invisible to it, which is stated in the ADR and the doc.
- Tagged `v0.1.0-alpha-9`; stack rebuilt, 167 migrations, doctor strict green.

## Addendum: streaming proven end to end; tenancy decision proposed

- **Streaming proof.** With `EVIDENCE_STREAM_ENABLED=true` on the dev stack, a
  `dev/smoke` stream, a scoped `evidence.write` token and a signed
  `detection-event`, the endpoint returned **202** and wrote one record
  (`detection-event`, status `unknown`, cursor `1`); the stream counters read
  accepted `1`, rejected `0`. Replaying the same body and cursor returned **200
  duplicate** with the same `evidenceId` and still one record. The stream was then
  disabled, the token revoked, and the endpoint returned to its default (env
  false): unauthenticated `401`, valid token `404`.
- **Push sources are created disabled.** The proof exposed a real flaw: both push
  paths created an enabled `EvidenceSource`, so the doctor warned about a source
  with no connector that never collected. A push source has no schedule; the
  snapshot API and the stream endpoint now create it disabled, and a test asserts
  it.
- **Multi-tenancy (ADR 0057, proposed).** The roadmap asked for the decision
  before the code: non-null `tenant_id` with backfill, server-side assignment, a
  base-model scope, storage/settings/jobs/portals isolation, and fail-closed
  behaviour. Nothing is implemented; a nullable, fail-open column is rejected.
- **Production promotion was not performed.** There is no production environment
  here; `docs/operations/production-promotion.md` is the path and the tag is the
  artifact.
- Doctor strict green again (**21 pass** on the container), audit ledger intact,
  167 migrations verified. Tagged `v0.1.0-alpha-10`.

The dev stack keeps the disabled `dev/smoke` stream and its single evidence record
as a record of the test; the secret was disabled and the token deleted.

## Addendum: audit coverage and a digest that missed the changes

- **The digest was hashing the wrong column.** Activity changes are stored in
  `attribute_changes` in this version of the activity package, so version 1 of the
  ledger hash covered an empty payload. Fixed by versioning rather than
  rewriting: new entries record `hash_version = 2` and hash the attribute changes
  and properties; version 1 entries verify with the old payload. A test tampers
  with `attribute_changes` and expects `altered`.
- **Coverage.** Twenty-two governance registers that had no activity logging now
  log an explicit field set: access grants and reviews, approval requests and
  steps, assets, assistant proposals, control attestations, crosswalks and
  validation rules, DLP policies, findings and suppressions, evidence sources and
  streams, exercises, findings, policies, acknowledgements and exceptions,
  protected resources, remediation tasks and vendor subcontractors. Free text and
  credentials are excluded, and tests prove it for a suppression justification and
  an evidence-source configuration.
- 168 migrations; doctor strict green; tagged `v0.1.0-alpha-11`.

Still not implemented, by decision: shared-instance multi-tenancy (ADR 0057 is
proposed) and an actual production promotion (no production environment here).

## Session close

The branch is released through `v0.1.0-alpha-11`; every implementable item from
this session is committed and pushed, the tree is clean, the Compose stack is
healthy, `doctor --strict` is green and the audit ledger verifies.

What is left is not a task that another commit can finish:

1. **Shared-instance multi-tenancy.** ADR 0057 is a decision record, not a
   backlog item. Building it means a non-null tenant key on every tenant-owned
   table, a same-migration backfill, a base-model scope, storage/settings/jobs/
   portal isolation and an adversarial isolation suite. A partial version is the
   failure mode the roadmap names; it must be accepted and scheduled as its own
   release, not appended to a session.
2. **Production promotion.** There is no production host, backup or operator
   credential in this environment. `docs/operations/production-promotion.md` is
   the runbook; executing it is an operator action.

Everything else the handoff listed — the auditor portal, assistant, access rules,
security architecture, access governance and its decision endpoint, Gophish, DLP
policy and suppressions, streaming, assistant proposals and the audit ledger — is
implemented, tested, documented and released.

## Still open, stated plainly

1. **Evidence streams are CLI-only.** There is no screen for the counters, last
   rejection reason or disabling a stream; an operator has to query MySQL.
2. **The assistant has no producer.** ADR 0055 is implemented and tested, but no
   question calls the proposal service, so the queue stays empty until one is
   wired as a reviewed use case.
3. **The immutable audit-log pillar is not started.** `activity_log` is still an
   editable table; applying the evidence-ledger pattern is the next large
   architectural change.
4. **Streaming is disabled** until an operator enables it and creates a stream.
5. The two assistant operations are the entire write surface; adding a third is a
   reviewed catalogue change, not a prompt edit.
